2. DEEP TECHNICAL AUDIT: CRITICAL LOGICAL BUGS & EDGE CASES FOUND
--------------------------------------------------------------------------------

CRITICAL BUG 1: Missing Timeframes (4h & 6h) in State Manager Database Load
- Location: state_manager.py (Line 93)
- Root Cause: StateManager.__init__ iterated only through ["15m", "30m", "1h", "2h"]
  when initializing active trades from SQLite database on startup.
- Impact: If a 4h (240m) or 6h (360m) trade was active during a server restart,
  StateManager failed to load those active trades from database into state cache.
- Resolution: Updated iteration to ["15m", "30m", "1h", "2h", "4h", "6h"].

CRITICAL BUG 2: Index Type Mismatch in Correlation Calculation
- Location: risk_engine.py (Lines 78-110 in calculate_portfolio_correlation)
- Root Cause: Target and position DataFrames were joined via pd.concat using raw
  indexes. When one DataFrame used integer millisecond timestamps and another used
  DatetimeIndex or float timestamps, the index join yielded 0 rows.
- Impact: len(combined) evaluated to 0, causing correlation check to return 0.0
  falsely, allowing correlated altcoins to bypass risk filters.
- Resolution: Applied pd.to_datetime normalization on timestamp columns before
  computing percentage returns and joining series.

HIGH SEVERITY ISSUE 3: Unbounded Memory Growth in MLOps Telemetry
- Location: mlops_engine.py (Lines 161-169 in IntervalPerformanceTracker)
- Root Cause: log_prediction appended every live prediction to an unbounded list.
- Impact: Memory steadily increased over long runtimes across multiple timeframes.
- Resolution: Enforced a 500-entry sliding window cap inside log_prediction.

MEDIUM SEVERITY ISSUE 4: Non-Monotonic Bin Edge Exception in PSI
- Location: mlops_engine.py (Lines 88-110 in calculate_psi)
- Root Cause: np.percentile produced duplicate bucket boundaries on low-variance
  data, causing np.histogram to throw a ValueError.
- Resolution: Applied np.unique and monotonic step padding on bucket boundaries.

RESOLVED ISSUE 5: Windows Terminal Encoding Bottleneck
- Location: main.py (Line 28 in CircularLogBuffer)
- Resolution: Replaced unicode emojis with ASCII tags ([+]) and added UTF-8 binary
  stream fallback (sys.stdout.buffer with errors='replace') to prevent Windows
  charmap / cp1252 UnicodeEncodeError crashes.
