2. COMPREHENSIVE ARCHITECTURAL COMPARISON

A. Infrastructure & System Integrity

* Decoupled Retraining
  - Before: Retrainer and journal digest ran as background threads inside the main execution process, causing thread-locking and disk thrashes.
  - After: Fully isolated in a separate subprocess (retrain_worker.py). Main loop is 100% protected.

* State Durability & Backups
  - Before: Local SQLite writes without schema checks or automated backups.
  - After: Executed database integrity checks at startup and compressed nightly archives backed up automatically.

* API Data Caching (OI/Funding)
  - Before: Startup re-fetching of entire history on every reload, taking 3-5 mins.
  - After: Persistent CSV cache under kline_cache/ fetching only the delta. Startup time reduced to under 10 seconds.

* Observability & Health
  - Before: Zero remote observability without SSH.
  - After: Flask /api/health endpoint tracking websocket connection states, uptime, active positions, and weights age.

B. Risk Management & Position Sizing

* Position Sizing Rules
  - Before: Standard Quarter-Kelly scaling with basic caps. Left the account vulnerable to fat-tail events.
  - After: 95% CVaR tail-loss constraint limiting positions so total risk never exceeds a 5% Daily Loss Budget.

* Stress-Test Covariance Matrix
  - Before: Static correlation matrix checking historical pairs. Fails during market panics.
  - After: Under high volatility (Z-score > 2.0), correlations are forced to a stressed state of 0.95, dynamically shrinking position sizes.

C. Execution & Microstructure Protection

* Order Execution Mechanics
  - Before: Limit order chasing up to 5 times (60s), regardless of market momentum. Left the bot exposed to buying the falling knife.
  - After: Volatility monitor checking 1m ATR Z-scores. Swaps to instant Taker IOC execution when Z-score > 3.0 to bypass the queue.

* API Rate Limiting
  - Before: No header tracking, leading to sudden 429 blocks.
  - After: Real-time headers parsing (X-Bapi-Limit-Remaining) with a 1-second auto-throttle fallback.

D. Model Quality & Machine Learning

* Meta-Learner Calibration Decay
  - Before: Stacking calibration with equal weights on all historical validation data.
  - After: Exponential time-decay validation weights, prioritizing recent market relationships.

* Regime-Specific Feature Registry
  - Before: Singular feature registry file shared globally, over-purging indicators.
  - After: Independent RFECV runs for Trending vs Ranging regimes. Models dynamically loaded with correct feature shapes.
